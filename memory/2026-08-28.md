## 框架代码审查 + 消除 any

对 node-laravel 框架全量代码做了一次「逻辑审查 + 构建验证 + any 收窄」：

### 完成事项
1. **构建/类型检查**：`npx tsc --noEmit` 与 `npm run build` 均 0 错误，`npm test`（vitest）13 用例全绿。
2. **消除 any**：源码中已无任何 `any` 类型定义（仅剩 2 处注释提及）。
   - `configLoader.ts`：`config()` 改为泛型 `config<T = unknown>(path, defaultValue?)`，导出 `AppConfig/DatabaseConfig/CacheConfig` 类型；`configs` 由 `Record<string, any>` 改为字面量推断类型。
   - `events.ts`：`EventHandler`/`publish`/`broadcast` 的 `any[]` 全部收窄为 `unknown[]`，JSON.parse 结果显式断言。
   - `BaseModel.ts`：28 处 `Record<string, any>` → `Record<string, unknown>`；`buildQuery` 的 id 过滤用 `FilterCondition` 类型守卫收窄。
   - `JsonRpcClient.ts`：JSDoc 中的 `@param {any}` 改为 `unknown/RpcServerConfig`。
   - 连带修复 ~20 处 `config()` 调用点，显式标注 `<string>/<number>/<AppConfig>` 等类型参数。
3. **顺带修复的 bug**：
   - `config/cache.ts` `port` 改为 `parseInt`（与 database.ts 一致，修复 string 端口传给 redis 的隐患）。
   - `ForceHttps.ts` / `public/index.ts` 中 `app.app_url` → `app.url`（原 key 不存在，恒空串）。
   - `SecretRow`（framework.d.ts 与 express.d.ts 两处）补充 `appIv?: string`。

### 遗留发现（未改，待决策）
- **配置 key 不一致**：`routes/web.ts` 读 `app.web.front.port`、`routes/console.ts` 读 `app.web.console.port`，但 `config/app.ts` 实际为 `front.port`（无 `web`、无 `host`），`FRONT_PORT` 环境变量实际被忽略。

## 全量代码审计（第三轮）

对 `src/` 全部 113 个 .ts（约 10357 行）做全面审计，报告输出至 `docs/audit-2026-08-28.md`。

**结论**：类型/构建/any/SQL 注入/危险函数均干净；架构分层与 ORM 能力收敛得当。发现 4 个 P1 + 18 个 P2/P3。

**P1 高危**：
1. `CacheRedisDriver.ensureReady` 连接失败死循环（.catch 吞错 → 无限轮询，Redis 不可用所有缓存操作永久挂起）。
2. `cryptoTool.decrypt` JSON.parse 失败时错误信息拼入明文，经 `DecryptRequest` log.error 写入日志（明文泄露）。
3. `events.ts` crossProcessBus.subscribe 存 localHandlers，仅靠 Redis 回环触发；Redis 不可用本地事件静默丢失。
4. APP_KEY 长度校验不一致（configLoader 只 warn，cryptoTool 强制 throw；key 未派生 vs iv 派生）。

**P2 关键**：BaseModel.sanitizeValue number clamp 提前 return 中断、nonce/remember 互斥锁 check-then-set 竞态、hashPassword 调试残留 + scrypt 参数无上限、Container.resolve 异步 resolver 类型不一致、QueueWorker JSON.parse 在 try 外、BaseRequest.castValue `Boolean("0")=true` 语义反转等。

**状态**：仅审计未修复，等待用户决策是否修复 P1/P2。

## 审计问题全部修复（第四轮）

按用户「修复全部」要求，把审计报告 21 项问题（4 P1 + 11 P2 + 6 P3）全部修复：

**P1 高危**
1. `CacheRedisDriver`：`ensureReady` 改为带超时（`cache.connect_timeout`，默认 3000ms）快速失败，连接错误保留并抛出，不再无限轮询。新增 `add()`（Redis SET NX 原子操作）。
2. `cryptoTool.decrypt`：错误信息只保留 `decrypted length`，debug 输出去掉 `decryptedPreview` 明文片段。
3. `events.ts`：`publish` 本地直接触发 `localHandlers`（不再依赖 Redis 回环），Redis 广播携带 `localSourceId`（randomUUID）去重，避免本进程重复触发。
4. `configLoader.validateSecurityConfig`：APP_KEY 长度非 32 字节改为 `throw`（启动期拦截）。

**P2 关键**
5. `BaseModel` number 分支 string→number 时 minimum/maximum 同时 clamp（消除 early return）。
6. `AuthenticateSecret` nonce：`get+set` → `CacheService.add()`（原子 SET NX），消除 TOCTOU。
7. `CacheService.remember` 互斥锁：同样改 `add()` 原子获取。
8. `hashPassword`：删除 `console.log('valid', valid)` 调试残留。
9. `hashPassword`：新增 scrypt 参数上限校验（N≤2^17、r≤32、p≤16），防 DoS。
10. `Container`：`Resolver<T>` 收窄为同步 `() => T`（消除 Promise 缓存类型不一致）。
11. `cryptoTool.decryptToken`：JSON.parse 失败改为抛错（不再静默返回 null）。
12. `QueueWorker.processJob`：JSON.parse 移入 try，损坏 payload 走 markFailed。
13. `BaseModel.insertMany`：过滤后空字段显式 throw（与 insert 一致）。
14. `CacheService.remember`：假值（0/false）也缓存（`!== null && !== undefined`）。
15. `BaseRequest.castValue`：boolean 显式映射（`"0"`→false），修复 `Boolean("0")=true` 反转。

**P3 规范/风格**
16. config/bootstrap 7 个文件 `@FilePath` 去前导斜杠。
17. `cryptoTool.ts` `@FilePath` 文件名 `CryptoTool.ts`→`cryptoTool.ts`。
18. config/bootstrap 目录统一为无分号风格（与 app 目录一致）。
19. `BaseModel` 注释去掉硬编码「74 个子类」。
20. `CacheRedisDriver.forgetByPattern` 统计日志降级为 debug（`app.debugger` 才输出）。
21. **密钥分离**：`CryptoTool.deriveEncryptionKey()` 用 HMAC-SHA256 域分离派生独立 AES 密钥；`EncryptResponse`/`DecryptRequest` 租户密钥改用派生密钥，`encrypt`/`decrypt` 签名支持 `Buffer` key。

**连带修复**：`CacheFileDriver.get()` 过期文件删除的双前缀 bug（`forget(this.prefix+key)`→`forget(key)`），`CacheDriver` 接口新增 `add()`，`config/cache.ts` 新增 `connect_timeout`。

**⚠️ 破坏性变更**：P3-21 密钥分离改变了租户 AES 加密密钥（旧密文用 `Buffer.from(appSecret)`，新密文用 `HMAC-SHA256(appSecret)`），已有加密数据需重新加密（项目尚在开发期，影响可控）。

**验证**：`tsc --noEmit` 0 错误、`npm run build` exit 0、`npm test` 13 用例全绿。

**过程教训**：用 `perl -pi -e 's/;\s*$//'` 去分号时，`\s*` 会吞掉换行符导致行合并（破坏了 cluster/configLoader/events/routeLoader 4 个文件），已用 Write 逐个重写恢复。正确写法应为 `s/;(\s*)$/$1/` 或逐字符处理，去分号务必先确认 `\s` 不会跨行。
