# 🚀 接口对接指南

本项目的接口设计遵循 **RESTful** 规范，并内置了企业级的安全加固方案（签名验证、响应加密、Token 自动续期、网关鉴权）。

> 接口路由示例见框架内置控制器：
> - Web 控制器 `src/app/Http/Controllers/Front/ExampleController.ts`（`GET /example`、`GET /example/:id`、`POST /example`）
> - API 控制器 `src/app/Http/Controllers/Api/ExampleUserController.ts`（`GET /api/example/users`、`GET /api/example/users/:id`）

---

## 一、 基础信息

* **Base URL**: `https://api.yourdomain.com/api`
* **Content-Type**: `application/json`
* **身份认证**: 使用 `Authorization: Bearer {token}` 放入 Header。

## 二、 安全校验逻辑 (Signature)

当接口要求签名验证时，前端必须在 Header 中携带 `x-sign` 和 `x-timestamp`。

### 1. 签名流程

1. 获取当前 **UNIX 时间戳** (秒)。
2. 将所有请求参数 (Query + Body) 按 **键名(Key) 字母升序** 排序（嵌套对象递归排序）。
3. 将排序后的参数序列化为 JSON 字符串。
4. 计算 `paramsDigest = SHA256(参数JSON)`。
5. 使用 **HMAC-SHA256** 算法，以密钥（已鉴权 appSecret，缺失时回退全局 `APP_KEY`）计算签名：`x-sign = HMAC-SHA256(paramsDigest, key)`。

> 旧版 `md5(sha256(params) + key)` 算法默认拒绝，仅当 `LEGACY_XSIGN_MD5=true` 时过渡兼容。

### 2. 代码参考 (Node.js)

```javascript
import crypto from 'node:crypto'

function sortObjectDeep(obj) {
  if (Array.isArray(obj)) return obj.map(sortObjectDeep)
  if (obj && typeof obj === 'object') {
    return Object.fromEntries(
      Object.entries(obj)
        .sort(([a], [b]) => a.localeCompare(b))
        .map(([k, v]) => [k, sortObjectDeep(v)])
    )
  }
  return obj
}

function getSignature(params, appKey) {
  // 1. 排序（Query + Body 合并，忽略 file/files/buffer 等二进制大字段）
  const sortedParams = sortObjectDeep(params)
  // 2. 序列化 + SHA256
  const paramsDigest = crypto.createHash('sha256').update(JSON.stringify(sortedParams)).digest('hex')
  // 3. HMAC-SHA256
  return crypto.createHmac('sha256', appKey).update(paramsDigest).digest('hex')
}
```

## 三、 响应格式与数据解密

### 1. 标准响应结构

```json
{
  "code": 200,
  "msg": "success",
  "data": "U2FsdGVkX19v...", // 如果开启了 RETURN_ENCRYPT，这里是加密串
  "is_encrypted": true       // 标识是否需要解密
}
```

> 成功响应通过 `res.success(data, code?, msg?)` 返回；失败通过 `res.error(code, msg)` 返回（`code` 为 12 位错误码，见本文档第六节）。

### 2. 解密逻辑

如果 `is_encrypted` 为 `true`，请使用 **AES-256-CBC** 算法，配合 `APP_KEY` 和 `APP_IV` 解密 `data` 字段。

## 四、 Token 无感续期 (Silent Refresh)

为了保证用户体验，框架支持无感续期。

1. 前端发送请求。
2. 若 Token 即将过期，服务端会在 **Response Headers** 中附加 `X-New-Token` 字段。
3. 前端 **必须** 检查每一条响应的 Header，若存在该字段，请立即替换本地存储的旧 Token。

### Axios 拦截器示例

```javascript
axios.interceptors.response.use(response => {
  const newToken = response.headers['x-new-token']
  if (newToken) {
    localStorage.setItem('token', newToken) // 自动更新本地 Token
  }
  return response
})
```

## 五、 网关鉴权 (AppId / AppSecret)

针对 **Server-to-Server** 或特定开放接口，需在 Header 中携带网关凭证：

* **app-id**: 分配的 AppID。
* **app-secret**: 动态计算的密文，算法如下：

```
app-secret = HMAC-SHA256(appId + timestamp, appSecret) + timestamp
```

其中：
- `timestamp`：当前 **UNIX 时间戳**（秒），密文末尾固定 10 位。
- `appSecret`：服务端分配的原始密钥。
- 时间戳有效期默认 1800 秒（`TOKEN_TIME` 可配），并允许 `MAX_FUTURE_SKEW`（默认 300 秒）时钟偏差。

### 网关鉴权请求示例 (Node.js)

```javascript
import crypto from 'node:crypto'

const appId = '10001'
const appSecret = 'YOUR_RAW_SECRET'
const timestamp = Math.floor(Date.now() / 1000).toString()

const digest = crypto.createHmac('sha256', appSecret).update(appId + timestamp).digest('hex')
const appSecretHeader = digest + timestamp // 末尾拼 10 位时间戳

// Headers: { 'app-id': appId, 'app-secret': appSecretHeader }
```

> 可选：携带 `x-nonce`（1-128 字符）防重放；生产环境建议启用。

## 六、 错误码说明

| 状态码 | 含义 | 处理建议 |
| --- | --- | --- |
| **401** | Token 失效 / 缺失 / 网关凭证错误 | 跳转登录页或检查 app-id/app-secret |
| **403** | 签名验证失败 / 权限不足 | 检查签名算法和密钥 |
| **404** | 资源不存在 | 检查请求路径与资源 ID |
| **422** | 参数校验失败 | 检查表单字段是否符合 rules() 要求 |
| **429** | 请求过于频繁 | 降低请求频率（限流） |
| **500** | 服务器内部错误 | 联系后端开发人员 |

> 完整 12 位错误码（状态码 + 目录码 + 文件码 + 错误序号）规范与文件码表，见 [docs/README.md](./README.md)「错误码规范」章节。

## 七、 调试建议

1. **开发环境**: 后端若开启 `APP_DEBUG=true`，响应结果中会包含 `stack` 调试信息。
2. **Mock 数据**: 建议使用 `Postman` 预先配置 Pre-request Script 来自动生成签名。
3. **追踪链路**: 后端开启 `TraceId` 后，请求头会携带 / 响应会回传追踪 ID，排查问题时可提供给后端。
